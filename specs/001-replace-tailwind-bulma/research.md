# Phase 0 — Research: Replace Tailwind with Bulma (standalone binary)

**Feature**: `001-replace-tailwind-bulma`
**Date**: 2026-05-19
**Source spec**: [`spec.md`](./spec.md)

This document resolves every `NEEDS CLARIFICATION` from the plan's
Technical Context and pins the implementation strategy for Phase 1.
Each subsection follows: **Decision** → **Rationale** → **Alternatives
considered**.

---

## 1. Bulma version and distribution

- **Decision**: Vendor Bulma **0.9.4** (the most recent stable
  `bulma.min.css` published on <https://bulma.io/documentation/>) as a
  single file checked into `internal/server/static/css/bulma.min.css`
  and mirrored into `internal/assets/static/css/bulma.min.css` so the
  Go `//go:embed all:static` directive picks it up at compile time.
  No Sass build, no node toolchain.
- **Rationale**: Bulma is published as a single, pre-minified
  CSS file (~190 KB raw, ~25 KB gzipped). Pinning it as a vendored
  artifact removes Sass/node entirely and matches Constitution Principle
  I (shallow dependency graph). A single file is trivial to update —
  drop the new file in, run the validation procedure, commit.
- **Alternatives considered**:
  - **Sass build with PurgeCSS**: smaller output (~30 KB raw) but
    requires Node, defeats FR-003.
  - **Bulma CSS variables fork (`bulma-css-vars`)**: theming flexibility
    we do not need.
  - **Pull from CDN at runtime**: violates FR-002 (no off-host
    requests).

## 2. JavaScript runtime for interactive widgets

- **Decision**: Use **Alpine.js v3** in its **CSP-safe build**
  (`@alpinejs/csp`), vendored as `vendor/alpine.csp.min.js` in both
  static directories. Default Alpine evaluates attribute expressions
  via `Function()` and requires `'unsafe-eval'`; the CSP build
  pre-restricts directives to property access only and works under
  the strict CSP we are committing to (see §4).
- **Rationale**:
  - Matches the `/speckit-clarify` decision (Alpine.js embedded).
  - The CSP build keeps the strict CSP achievable without
    `'unsafe-eval'`, satisfying FR-013.
  - All interactive needs are simple (toggle navbar burger, open/close
    modals, toggle filter dropdowns, drive log filter+pagination
    locally). None need arbitrary expressions.
- **Alternatives considered**:
  - **Default Alpine.js** plus `'unsafe-eval'`: smaller ergonomic
    hit, but contradicts the strict-CSP intent.
  - **HTMX**: excellent for server-rendered fragments but adds a
    round-trip for filter toggles that are pure client state. Could
    layer in later if needed; not required for this feature.
  - **Plain vanilla JS**: feasible but multiplies hand-written event
    listeners; higher long-term maintenance.
  - **Stimulus / Lit**: heavier dependency graph than necessary.
- **Constraint imposed**: every Alpine directive in templ files MUST
  be limited to property access, comparisons, and method calls — no
  arbitrary expressions, no inline arithmetic. We will lint this in
  PR review.

## 3. Icon set

- **Decision**: Hand-pick **~15–25 SVG glyphs** (status: running,
  success, failed, pending, idle, queued; actions: run, stop, refresh,
  copy, view; navigation: chevron-right, search, filter; misc: info,
  warning, error, check, x) from the **Heroicons v2 outline+solid**
  set (MIT license) and ship them as **a single SVG sprite** at
  `internal/server/static/icons/sprite.svg` (mirrored to
  `internal/assets/static/icons/sprite.svg`).
- **Rationale**:
  - One HTTP request, one cacheable artifact, well under 10 KB
    minified.
  - Heroicons are MIT-licensed, dense, visually consistent — a clean
    fit with Bulma's neutral aesthetic.
  - Inline `<use href="/static/icons/sprite.svg#run">` plays nicely
    with strict CSP and CSS recoloring via `currentColor`.
- **Alternatives considered**:
  - **Font Awesome free**: ~70 KB+ of webfont/SVG payload to cover
    25 glyphs.
  - **Inline SVG per templ file**: avoids the sprite request but
    duplicates SVG payloads across pages — worse cache behavior.
  - **No icons (color + text only)**: marginal UX regression on
    status-heavy views; rejected.

## 4. Content-Security-Policy posture

- **Decision**: Emit
  ```text
  Content-Security-Policy: default-src 'self';
                           script-src  'self' 'nonce-{NONCE}';
                           style-src   'self';
                           img-src     'self' data:;
                           font-src    'self';
                           connect-src 'self';
                           frame-ancestors 'none';
                           base-uri 'self';
                           form-action 'self';
                           object-src 'none'
  ```
  - A per-request nonce is generated by a new
    `CSPNonceMiddleware` that runs before `SecurityHeadersMiddleware`
    and is stored on `r.Context()`.
  - `SecurityHeadersMiddleware` reads the nonce from context and
    sets the `Content-Security-Policy` header.
  - `templ` templates receive the nonce through `BaseData.CSPNonce`
    and render it on every `<script>` tag they emit.
  - `'unsafe-inline'` and `'unsafe-eval'` are **removed** from
    `script-src`; `'unsafe-inline'` is **removed** from `style-src`.
- **Rationale**: Implements FR-013 and SC-009; matches Constitution
  Principle V (security boundaries are first-class). The Alpine CSP
  build (§2) makes `'unsafe-eval'` removable; the
  sprite/Bulma/Alpine embedded asset model makes `'unsafe-inline'`
  removable for both scripts and styles. Inline `style="..."` on
  templ-generated HTML must be eliminated as part of the templ
  rewrite.
- **Alternatives considered**:
  - **Keep `'unsafe-inline'`** (cheap, single-line change): rejected
    per clarification.
  - **Hash-based CSP** instead of nonce: works if every script body
    is static, but our setup permits an Alpine `script` tag
    parameterized by nonce — nonces are simpler to roll forward.
  - **Strict-Dynamic**: not needed; we have a fixed set of scripts.

## 5. Browser validation: `playwright-cli` skill workflow

- **Decision**: Document a **single validation procedure** under
  `specs/001-replace-tailwind-bulma/quickstart.md` plus a dedicated
  **test configuration** at `configs/playwright-test.yaml` (and a
  static seed of users/tasks). The assistant runs the procedure by
  invoking the `playwright-cli` skill against `http://localhost:8080`
  with the binary started locally. Per-scenario screenshots are
  written to `specs/001-replace-tailwind-bulma/artifacts/` and
  attached to the PR.
  - No Node toolchain, no committed `*.spec.ts` files, no headless
    CI suite are added by this feature (per clarification).
- **Rationale**: Matches the clarification. The validation
  procedure is reproducible, auditable, and AI-assistant-friendly
  while keeping the build graph clean (Constitution I).
- **Alternatives considered**:
  - **Pinned Node Playwright suite in CI**: deeper regression
    protection but contradicts the clarification and adds a Node
    toolchain.
  - **Manual checklist only**: no artifact trail; weaker assurance.
- **Open follow-up** (out of scope, documented for future work): if
  the team later wants CI-pinned regression coverage, the Playwright
  suite can be added alongside the assistant procedure without
  changing the binary.

## 6. Test configuration fixture

- **Decision**: Check in `configs/playwright-test.yaml` containing:
  - `server.port: 18080` (non-default to avoid local-dev conflicts)
  - `server.log_directory: ./.test-logs`
  - `server.session_timeout: 5m`
  - `auth.jwt_secret`: 32-byte placeholder; documented as test-only,
    rotated never; treated as low-sensitivity by reviewers.
  - `auth.users[0]`: `e2e-admin` with a known bcrypt hash for the
    password `e2e-password!`. The hash is generated once via
    `./runrun hash-password e2e-password!` and committed.
  - `tasks`: 3 deterministic tasks: `echo-ok` (single `echo hello`
    step, succeeds in <1 s), `fail-task` (single `false` step, fails
    quickly), `multi-step` (3 echo steps, 2 of which sleep 0.2 s)
    — enough to exercise success/failure/log-pagination journeys.
- **Rationale**: Deterministic fixtures keep the validation
  procedure stable and screenshot-comparable across runs. Tiny
  tasks keep the procedure under 10 minutes wall-clock.
- **Alternatives considered**:
  - **Generated random tasks**: bad for screenshot stability.
  - **Reuse `configs/example.yaml`**: depends on local environment
    and is not deterministic.

## 7. Bundle size budget

- **Decision**: After the migration, the embedded asset bundle MUST
  satisfy each of these budgets (measured at build time by a small
  helper task added to `Taskfile.yml`):
  | Asset | Limit (raw) | Limit (gzipped) |
  |---|---|---|
  | `bulma.min.css` | 250 KB | 30 KB |
  | `app.css` | 20 KB | 5 KB |
  | `vendor/alpine.csp.min.js` | 60 KB | 18 KB |
  | `main.js` + `log-viewer.js` | 25 KB | 7 KB |
  | `icons/sprite.svg` | 20 KB | 5 KB |
  | **Total embedded CSS+JS+icons** | **375 KB** | **65 KB** |
- **Rationale**: Sets a measurable backstop for Constitution
  Principle V; cheaper than the current Tailwind output (~36 KB
  minified-gzipped) only at the per-file level — total is comparable.
  Documented limits make growth visible in PRs.
- **Alternatives considered**:
  - **No budget**: easy to slip; reviewers lose a clear signal.
  - **Aggressive PurgeCSS pass on Bulma**: pulls Node back in.

## 8. Empty / loading / disconnected states

- **Decision**: Standardize five states with Bulma primitives:
  | State | Pattern |
  |---|---|
  | Page-level loading | Bulma `is-loading` button + `progress is-small is-primary` bar in the main content area |
  | Page-level empty | Centered `media`-style block with sprite icon, headline, helper text, primary CTA |
  | List/table empty | Inline neutral message + reset-filters link |
  | Inline error | Bulma `notification is-danger is-light` with action verb in the message |
  | WebSocket lost | Sticky bottom `notification is-warning` with "Reconnect now" button |
- **Rationale**: Consistent presentation across pages, addresses
  FR-008 (actionable error UX) without inventing new components.
- **Alternatives considered**:
  - **Per-page bespoke styles**: rejected — diverges from FR-008's
    consistency intent.

## 9. Asset embedding strategy & dual-directory sync

- **Decision**: Keep the existing two-tree layout
  (`internal/server/static/` for dev edit, `internal/assets/static/`
  for `//go:embed`). Add a `task sync-assets` step that copies the
  source tree to the embed tree and is invoked automatically by
  `task build-all` and `task build`. The Taskfile guarantees the
  embed tree is always in sync at build time.
- **Rationale**: Removes the manual-sync footgun documented in the
  project memory (`MEMORY.md` notes "Both directories must be kept
  in sync!"). One automated step solves it.
- **Alternatives considered**:
  - **Single directory + `//go:embed`**: would require restructuring
    handlers that reference the dev path; larger blast radius for
    this feature.
  - **rsync watcher**: more complex; build-time copy is enough.

## 10. Inline event-handler removal (CSP migration)

- **Decision**: Eliminate every `onclick=`, `onsubmit=`,
  `onchange=` attribute from templ files. Replace with one of:
  - **Alpine directive** (`@click`, `@submit`, `@change`) bound to
    a method declared in `x-data` — works under CSP build.
  - **Data attribute** (`data-action="run-task"`) + a delegated
    listener in `main.js` for behavior that is not local to a
    component (e.g. the `runTask`, `clearFilters` global helpers).
- **Rationale**: Inline handlers violate strict CSP. The two
  patterns above cover every current call site:
  - `task_detail.templ` `onclick="runTask(event)"` → data-action.
  - `dashboard.templ` `onclick="clearFilters()"` → data-action.
  - Future log-filter/pagination toggles → Alpine `x-data` on the
    log container.
- **Alternatives considered**:
  - **Loosen CSP**: rejected per §4.
  - **Move handlers to `<script>` blocks with nonces**: works but
    less maintainable than data-action delegation.

## 11. Cache strategy for embedded assets

- **Decision**: Continue serving embedded static files through the
  existing `internal/assets.NewStaticFileServer`, which sets a
  `Cache-Control: public, max-age=31536000, immutable` header for
  files under `/static/`. **Append the build's short Git SHA as a
  query string** (`?v={SHA}`) to every `<link>` and `<script>` URL
  emitted by the base layout so updates invalidate caches naturally.
- **Rationale**: Strict CSP + long cache headers means stale assets
  could otherwise survive a deploy. Query-string cache busting is
  the simplest fix that does not require fingerprinted filenames.
- **Alternatives considered**:
  - **Content-hash filenames**: cleaner, more invasive; defer to a
    future feature.
  - **No cache busting**: risks confusing operators post-deploy.

## 12. Browser support matrix

- **Decision**: Validate on **Chromium**, **Firefox**, and **WebKit**
  in their current stable releases (matches Bulma's stated support
  matrix). Phone-size validation is performed at the Chromium
  device emulation `iPhone SE (375 px)` preset.
- **Rationale**: FR-005 names these three; Bulma drops IE so we do
  too. Single phone preset is sufficient for the SC-004 check.
- **Alternatives considered**:
  - **Multi-device matrix**: extra runtime; defer to future a11y/UX
    work.

## Open / deferred (intentionally out of scope)
